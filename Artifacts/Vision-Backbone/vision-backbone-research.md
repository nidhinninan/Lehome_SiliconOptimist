# LeRobot Vision Backbone Research Summary

This document consolidates the findings from research into vision backbones for Diffusion Policy (DP) training within the `lerobot` ecosystem, updated with training speed estimates from an RTX A4000.

## 1. Native LeRobot Support
LeRobot provides built-in support for several vision backbones via `torchvision`.

- **ResNet Family**: `resnet18` (default), `resnet34`, `resnet50`, etc., are supported out-of-the-box.
- **Config**: Configurable via `policy.vision_backbone=resnet18` in the CLI.

## 2. Advanced Backbones (CLIP vs. DINO)
**Are CLIP or DINO supported out-of-the-box for Diffusion Policy?**
**No.** The standard `DiffusionPolicy` class hardcodes the assumption of a 2D CNN feature map (followed by a `SpatialSoftmax` layer). It does not natively support 1D token sequences like those generated by standard ViTs.

**CLIP vs. DINO for Cloth Folding:**
- **CLIP (Contrastive Language-Image Pretraining)**: Excels at semantic understanding (e.g., "this is a red shirt"). Useful for language-conditioned tasks, but less precise for spatial localization.
- **DINO (Self-Supervised Vision Transformer)**: Generates exceptionally dense "spatial features." It naturally clusters object parts (e.g., separating the sleeves from the torso) without any semantic labels. 
- **Verdict**: For highly deformable tasks like folding cloth—where tracking spatial features and wrinkles is paramount—**DINO (specifically DINOv2 or DINOv3) is significantly better**. DINO representations have been shown to outperform CLIP for fine-grained visuomotor control.

**How to implement them:**
To use CLIP or DINO, use LeRobot's **"Bring Your Own Policy" (BYOP)** framework:
1. Subclass `PreTrainedConfig` and `PreTrainedPolicy`.
2. Define a custom `ObservationEncoder` that uses the `transformers` library (e.g., `Dinov2Model` or `CLIPVisionModel`).
3. Extract the `CLS` token (or pool patch tokens), reshape it, and pass it to the Diffusion U-Net's conditioning mechanism.

## 3. Training Speed Estimates (RTX A4000)
Based on the provided log `dp_top_short_training_93of150.log` (batch size = 8, ResNet-18, random weights):

| Backbone | Parameter Count | Measured/Estimated Speed | Est. Time per 1,000 steps |
| :--- | :--- | :--- | :--- |
| **ResNet-18** (Baseline) | 11.7M | `~0.460 sec / step` | ~7.6 mins |
| **ResNet-34** | 21.8M | `~0.600 sec / step` | ~10 mins |
| **DINOv2 ViT-Small** | 21M | `~0.550 sec / step` | ~9.1 mins |
| **CLIP ViT-Base/16** | 86M | `~0.700 sec / step` | ~11.6 mins |
| **DINOv2 ViT-Base** | 86M | `~0.700 sec / step` | ~11.6 mins |

*Larger models will increase VRAM utilization. If batch size 8 OOMs with ViT-Base, dropping to batch size 4 will roughly double the train time.*

## 4. Minimal Performance Sweep Methodology
You do not need to run 150K steps to observe differences in vision representations. A "Micro-Sweep" focuses on early convergence:

1. **Stop at 10,000 Steps**: 10K steps takes **~1.5 hours** per run (less for smaller backbones). 
2. **Evaluate in Sim**: Run a 50-episode eval against the Isaac Lab simulation. 
3. **What to look for**: A model with a stronger spatial backbone (DINO) or pretrained ImageNet weights will show significantly higher success rates at 10K steps than random weights, as it skips the "learning to see" phase.

### `controlledSweep_v2` (finalized micro-sweep)

Named sweep: **controlledSweep_v2**. Train **10,000 steps** per run; **50-episode** Isaac Lab eval on the 10k checkpoint. Hold policy/dataset/sim settings constant except where noted; prefer batch size **8**, and if ViT-Base OOMs use **4** and label the run.

| Run | Backbone | Stack | Pretrain | Notes |
| :--- | :--- | :--- | :--- | :--- |
| **A** | `resnet18` | Native DP (`vision_backbone=resnet18`) | ImageNet | `use_group_norm=false` (required for torchvision ImageNet weights). Best traditional baseline. |
| **B** | DINOv2 ViT-Small | BYOP, frozen backbone | DINOv2 | Dense spatial features (~21M params). |
| **C** | CLIP ViT-B/16 | BYOP, CLS (or fixed pool), frozen | CLIP | Semantic / larger scale (~86M); not param-matched to A/B. |
| **D** | `resnet18` | Same native path as **A** | **Random init** | Pretraining control: same architecture as A, no ImageNet load. |

**Comparisons:** **A vs D** isolates pretraining at fixed ResNet-18 architecture. **A vs B vs C** compares representation families at early (10k) convergence.
